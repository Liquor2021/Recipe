# NiniMenu 使用说明

> 一款温馨的每日菜单推荐与食谱管理应用，告别"今天吃什么"的纠结。

## 快速开始

1. 运行 `ninimenu.exe`（Windows）或 `./ninimenu`（Linux）
2. 浏览器打开 `http://localhost:8080`
3. 输入应用密码登录（默认 `nini123`）
4. 管理后台地址 `http://localhost:8080/admin`，默认密码 `nini123`

> 首次运行可在同目录下创建 `.env` 或 `env.bak` 文件修改端口、密码等配置。
>
> 默认密码和签名密钥是公开的，只适合本机试用。家里其他设备也要访问（局域网/公网）前，先在 `.env` 里改掉这三项再重启，否则管理后台会一直提醒：
>
> ```
> APP_PASSWORD=家人用的密码
> ADMIN_PASSWORD=管理后台密码
> JWT_SECRET=一串随机的长字符
> ```

## 功能介绍

### 智能推荐

- **午餐/晚餐推荐** — 根据菜品类型与历史记录智能推荐，自动排除近期重复
- **心情推荐** — 选择当前心情（开心、疲惫、想偷懒、想吃辣、想养生），获得匹配菜品
- **转盘抽奖** — 美食转盘随机选菜
- **盲盒惊喜** — 翻牌揭晓今日惊喜菜品
- **收藏加权** — 收藏的菜品推荐权重更高

### 明天吃什么

- 偏好过滤：快速/清淡/辣/收藏/均衡
- 设置目标道数，一键生成明日菜单
- 支持换菜、替换单道
- 查看菜谱后返回，保留当前标签页中未保存的明日菜单；草稿只用于原来的目标日期。计划在别处取消、改期或调整份量后，会保留草稿并展示最新安排，由你选择“保留草稿继续编辑”或“载入最新菜单”，不会直接覆盖当前选择
- 保存时一起更新明日菜单和对应的买菜需求；保留的菜沿用原记录与份量，取消的菜隐藏买菜需求

### 食谱管理

- 菜品信息：名称、图片/多图、视频、分类、口味
- 详细做法：食材、调料、步骤（支持计时）、烹饪时间、难度等级
- 烹饪模式：步骤引导，计时提醒
- 做菜计时支持暂停、继续和重置；切回页面时按实际经过时间校正，时间到后由你确认下一步，不会自动跳步
- 做菜页读取菜谱或计划失败时可直接重试或返回菜品列表；进入做菜后后台更新失败会保留步骤和计时，计划重新核对成功后才能记录已吃
- 菜品启用/禁用、克隆、排序
- 菜品列表进入详情再返回，保留搜索、分类、口味和浏览位置；加载失败可原地重试
- 菜品列表的午餐、晚餐按钮在操作期间显示转圈，等待菜单状态确认后才能再次点击；其他菜仍可操作。菜单状态读取失败时可重试

### 周计划 & 购物清单

- 一键生成本周午餐/晚餐菜单
- 点开今天或之后的一天可单独换菜。重新生成、换菜保存失败时保留原安排；读取失败时可重试，已有菜单会继续显示上次成功读取的内容
- 购物清单自动汇总食材，按蔬菜/肉类/配料/其他分类
- 支持勾选与库存标记
- “更多”页顶部查看今天和明天的买菜清单；可“只看待买”，隐藏已买和家中已有食材，常备调料仍单独收起
- 明日菜单的“买菜清单”入口直接定位清单；“复制待买”只复制尚未准备的食材，展开常备调料时一并复制缺少的调料
- 买过食材后又加菜或增加份量，会保留原采购量，只把新增差额列为待买；“放进冰箱”也只加入尚未入库的采购量。文字用量或单位不一致时会提示“用量待核对”
- 清单显示后，若计划、份量或采购状态在另一处发生变化，旧清单的勾选或取消勾选会提示“买菜清单已变化”并刷新；核对最新数量后再操作，旧页面不会直接确认新增的采购量

### 冰箱库存

- 按食材名搜索库存，并切换“全部／临期／已过期”。临期指今天至两天后到期，过期单独列出；同名食材只显示符合条件的批次
- 查看菜谱再返回时保留搜索和筛选；首页的临期提醒直接打开对应筛选
- “清理这 N 批”只移出当前搜索和筛选结果中的过期批次，确认弹窗会说明范围；清冰箱推荐仍基于全部可用库存
- 编辑库存时若另一处已修改同一批次，会保留当前草稿并提示读取最新库存后再确认；清理过期时也会重新核对日期，跳过已修正保质期的批次

### 记录与回顾

- 用餐记录：区分“计划”“已吃”“已取消”。点菜先加入计划，吃过后在记录页标记已吃，或在做菜模式完成时确认；日期过去不会自动算吃过
- 取消计划会隐藏对应买菜项目，恢复时保留原来的用量、已买与已入库标记；确认已吃后才计入饮食报告、做饭次数和相关成就
- 记录页的“待完成”汇总各个月份的计划，可加载更多；支持移到明天、选择日期或更换餐次，份量和购物状态一起保留
- 每顿的库存扣减会保存明细。做完后可选择稍后再扣，再从记录页“补扣库存”；“库存记录”中可以撤销扣减。旧记录可能曾手动扣过库存，补扣前请核对实际数量
- 误点已吃可选择“撤销已吃”，恢复为计划并清空该条记录的评分、心情和成品照；本次库存扣减会一并撤销。相关库存若已被后续操作改动，会提示冲突并保持现状，可先撤销后续扣减
- 菜谱份量：选择“原量 × N”后保存，买菜数量、做菜食材卡和库存剩余建议使用同一份量；“适量”等文字用量保留原文
- 已吃记录可以评分、添加备注与成品照片。升级前的记录按原有日期规则一次性迁移，以保留历史统计
- 删除当天照片保留原备注和心情；照片上传完才可保存评价，取消或切换评价后旧上传不会进入新草稿
- 饮食报告的“顿数”按日期和午餐／晚餐统计，同一餐多道菜只算一顿；菜品次数仍分别计算
- 饮食报告读取失败会提示重试，不会把失败显示为零次做饭；有缓存时保留上次成功读取的报告
- 照片墙：时间线展示美食照片与心情
- 全屏照片预览在横竖屏切换后保持当前照片居中，切换过程中也可继续翻页
- 历史回顾：查看过往用餐记录

### 成就系统

- 80+ 成就自动解锁（初入厨房、连续七天、百菜斩、粤菜大师等）
- 按用餐/心情/推荐/照片/收藏/购物等维度自动检测
- 支持管理后台手动解锁

### 管理后台

- 仪表盘：菜品数、记录数、分类分布、热门菜品、周趋势
- 菜品 CRUD：搜索、筛选、分页、批量操作、多图上传
- 菜品或记录删除失败会显示原因并保留列表，方便重试；记录还有有效库存扣减时，可通过提示进入用餐记录撤销扣减后再删。末页最后一项删除成功后，列表会回到仍有效的页码
- 编辑菜谱时先读取已有内容；后台刷新发现新版会保留当前输入，由你选择载入最新内容或保留当前编辑。图片上传完成后才能保存，替换主图以最后一次选择为准，多图上传会提示实际成功和失败数量
- 图片上传会检查内容是否完整可读；损坏文件会提示重新选择，压缩失败时只允许使用已验证可读的原图
- 语录管理、成就管理、记录管理
- 系统设置：重复天数、每日菜品数、分类、口味、应用名称
- 设置读取失败时暂停修改，点击“重新读取设置”成功后再操作；后台刷新失败会保留上次读取的设置和当前输入，避免把未读到的成员或忌口当成空列表保存

## 替换应用 Logo 图标

如需更换 NiniMenu 的应用 Logo（PWA 图标、浏览器图标等），请按以下流程操作：

### 步骤一：使用 GPT 生成菜品图片

使用 GPT 图像生成模型（如 `gpt-image-2`），生成 1:1 正方形菜品照片。

推荐 Prompt 模板：

```
生成菜品的照片 仅需要简单 突出菜品主题 色香味俱全食欲大增即可 菜品为[菜名] 将宽高比设为 1:1
```

项目内置了批量生成脚本（需配置 API Key）：

```bash
# 编辑 dish_images.txt 填入菜品名和输出路径，然后运行：
uv run python scripts/generate_dish_images_batch.py
```

也可单张生成：

```bash
uv run python scripts/generate_dish_image.py --prompt "菜品为青椒肉丝 将宽高比设为 1:1" --output output.png
```

菜品图片生成后通过管理后台上传即可，无需经过后续步骤。以下步骤二至步骤四仅适用于**制作和替换应用 Logo 图标**。

### 步骤二：使用 GPT 生成 Logo 图片

使用 GPT 图像生成模型生成 NiniMenu 品牌 Logo，推荐使用以下 Prompt：

### 步骤三：使用 imgtool.exe 去除白边并生成多尺寸图标

GPT 生成的 Logo 图片带有白色背景，需要使用 `backend\imgtool.exe` 处理：

```bash
# 基本用法：去除白边、裁剪到内容、生成多尺寸 PNG
backend\imgtool.exe logo.png

# 指定输出目录
backend\imgtool.exe -o output_folder logo.png

# 跳过裁剪（仅去白边，保留原始画幅）
backend\imgtool.exe -no-crop logo.png

# 仅生成多尺寸图标，不去白边、不裁剪
backend\imgtool.exe -no-trim logo.png

# 调整白边阈值（0-255，越高越严格，默认 240）
backend\imgtool.exe -t 250 logo.png
```

`imgtool.exe` 会自动完成：
1. 从边缘开始泛洪填充，将白色区域变为透明
2. 裁剪到非透明内容区域
3. 生成 6 种尺寸的 PNG 图标：**32×32、64×64、128×128、180×180、256×256、512×512**

### 步骤四：在线压缩图片

生成的多尺寸 PNG 文件可能较大，需要在线压缩：

1. 打开 [iloveimg 图片压缩](https://www.iloveimg.com/zh-cn/compress-image)
2. 上传步骤三生成的所有 PNG 文件
3. 使用默认压缩设置完成压缩
4. 下载压缩后的文件

### 步骤五：替换 static 中的图片文件

将压缩后的图片文件放入 `static/` 目录（对应 `backend/static/`），替换原有同名文件：

| 文件 | 用途 |
|------|------|
| `32.png` | 最小图标 |
| `64.png` | 小图标 |
| `128.png` | 中等图标 |
| `180.png` | Apple Touch Icon |
| `256.png` | 大图标 |
| `512.png` | PWA 启动图标 |

## 常见问题

**Q: 忘记密码怎么办？**

A: 在运行目录创建 `.env` 文件，设置 `APP_PASSWORD=新密码` 和 `ADMIN_PASSWORD=新密码`，重启即可（顺手把 `JWT_SECRET` 也设成一串随机字符）。

**Q: 数据存在哪里？**

A: SQLite 数据库文件位于 `data/ninimenu.db`。服务每天会自动备份一份到 `data/backups/`（保留最近 7 份），管理后台「设置 → 数据备份」也能随时下载一份。上传的图片在 `uploads/`，原图备份在 `uploads_backup/`。

**Q: 如何修改端口？**

A: `.env` 中设置 `PORT=新端口号`，重启生效。

**Q: 手机可以用吗？**

A: 支持手机浏览器访问，支持 PWA 添加到主屏幕。
